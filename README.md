# Cedarline — Behavioral Sequences in App-Based Investment Frauds

A 2×2 between-subjects oTree v5 experiment.

**Conditions:** Neutral UI vs Manipulative UI × 0% vs 35% apparent return  
**Platform name (fictional):** Cedarline  
**Prize:** 4 unique Rs 250 gift vouchers (lottery weighted by final balance)

---

## Quick Start (Local Dev)

```bash
# 1. Install dependencies (Python 3.10+ required; uses your system Python)
pip install -r requirements.txt

# 2. Reset the database (creates db.sqlite3)
otree resetdb

# 3. Start the dev server
otree devserver
# → Open http://localhost:8000
```

The dev server exposes four forced-cell session configs (only visible when
`OTREE_PRODUCTION` is **not** set):

| Config name | Cell |
|---|---|
| `dev_neutral_0pct` | Neutral UI / 0% reward |
| `dev_neutral_35pct` | Neutral UI / 35% reward |
| `dev_manip_0pct` | Manipulative UI / 0% reward |
| `dev_manip_35pct` | Manipulative UI / 35% reward |

> **Note:** The Windows sandbox has no network access, so `pip install`
> must be run outside the sandbox (or use the system pip directly).

## Architecture Notes

### Money math
All monetary arithmetic uses `logic/ledger.py` with exact `Fraction` values.
Amounts are converted to `int`/`float` **only** at the oTree field boundary.
No arithmetic in templates or pages.

### Assignment (concurrency)
Balanced 2×2 block-shuffle stored in `assignment_state.json` under a
file-level OS lock (`msvcrt` on Windows, `fcntl` on POSIX).

**Safe for:** single-process Uvicorn (default oTree production setup).  
**Not safe for:** multi-worker gunicorn across multiple machines. If you
scale horizontally, replace with a Postgres sequence or Redis counter.

### Pool outcomes
Pre-generated per-condition shuffled blocks in `pool_sequences.json`.
Drawn once per participant **after R is submitted** (in S4's
`before_next_page`), stored and never re-drawn on refresh.

### Lottery contact data
Stored in `lottery_contacts.sqlite3` (a separate file, **never** in
oTree's `db.sqlite3`). Linked to participants only via a random UUID
`claim_token` stored in `Player.claim_token`. Contact info never appears
in any oTree data export.

### Timer (manipulative arm)
The 60-second urgency countdown is **non-binding**. The deadline is stored
server-side once (at first render of any investment stage for a manipulative
participant). Every subsequent render computes `remaining = deadline - now()`
so refresh never resets the timer. At zero the banner shows "Window extended"
with zero side effects.

## Production Deploy

### Environment variables

| Variable | Required | Description |
|---|---|---|
| `OTREE_PRODUCTION` | Yes — set to `1` | Hides dev-only session configs |
| `OTREE_ADMIN_PASSWORD` | Yes | Admin panel password |
| `OTREE_AUTH_LEVEL` | Recommended | Set to `STUDY` to require login |
| `DATABASE_URL` | Yes in production | Postgres URL (see below) |
| `OTREE_SECRET_KEY` | Yes in production | Long random string |

### Database

oTree uses `DATABASE_URL` for its own database. Use Postgres in production —
ephemeral disk hosts (Heroku, Railway, Render) **wipe SQLite on redeploy**.

```
DATABASE_URL=postgresql://user:password@host:5432/dbname
```

The lottery contact database (`lottery_contacts.sqlite3`) is a **separate**
SQLite file that is NOT managed by `DATABASE_URL`. It needs a **persistent
volume** mounted at the project root. Configure your host to mount a
persistent disk at this path.

### Single-worker requirement

Run with a **single Uvicorn worker** to keep the file-lock assignment
strategy safe:

```bash
# Heroku Procfile
web: otree production

# Or with uvicorn directly
uvicorn otree.asgi:application --workers 1 --host 0.0.0.0 --port $PORT
```

### Quick deploy checklist

```bash
export OTREE_PRODUCTION=1
export OTREE_ADMIN_PASSWORD=<strong-password>
export OTREE_AUTH_LEVEL=STUDY
export DATABASE_URL=postgresql://...
export OTREE_SECRET_KEY=<long-random-string>

otree resetdb
otree production
```

## Money Math Rules (enforced)

- All amounts computed as `Fraction` via `logic/ledger.py`
- Converted to `int`/`float` ONLY when assigned to oTree fields
- No arithmetic in templates or pages
- Templates receive pre-converted integers

Ledger formulas (DO NOT CHANGE):
```
platform_balance(g, R, r) = 100(1+g) + R(1+r)
cash(R)                   = 1000 - 100 - R
final_balance(…, pay)     = cash - F + P  if pay
                          = cash           if not pay
classify(…)               = "net_loss_payment"      if pay and P < F
                          = "forgone_gain_abandonment" if not pay and P > F
                          = "indifferent"/"ok"       if P == F
```
